01 · How the money is made

Three return sources, one hurdle

The T-bill collateral earns roughly the hurdle by itself. The agents exist to add the volatility premium and the macro tilt on top, while keeping crash losses inside a fixed budget.

Collateral≈ Fed funds≥ 85% of NAV in T-bills or SGOV/BIL. Options are margined against them, so the cash keeps earning.

EngineVolatility risk premiumImplied vol usually exceeds realized. Selling ~16Δ options at 30–60 DTE harvests the gap.

−

05 · Harness engineering

Agent = model + harness

The model supplies judgment. The harness is everything around it: what each agent sees, which tools it may call, how its output is checked, where state lives, what it is forbidden to do, how every step is recorded and how the system learns. Full write-up in docs/design/HARNESS.md.

Computational (code)
Inferential (a model judges)

Agent charters, playbooks, lessons accepted from post-mortems
Sensors
check after acting
Schema validator, citation checker, freshness checker, numeric consistency, policy engine, stress engine

1Instructions & context

AGENTS.md is a short map. One versioned charter per agent. Context packs (≤ 30k tokens) are compiled from the database by code and hashed, so we can reproduce exactly what an agent saw. Stable prefix is prompt-cached.

2Tools, least privilege

Research agents are read-only. Only five desks get web search, on allow-listed domains. Numbers come from tools, never mental math. The structurer picks candidate IDs. No model can reach the broker.

3State & memory

Postgres is the system of record. Working memory = context pack; episodic = prior reports and outcomes; semantic = lessons you accepted. Runs checkpoint per step and resume after a crash.

4Orchestration

A fixed DAG in code with per-step budgets for tool calls, dollars and time. Remediation is appended as a new turn; history is never edited. A failing desk degrades to last week's report, flagged stale.

5Verification

Schema, citation, freshness and numeric sensors on every output; policy and stress engines on every proposal; adversarial review on every plan.

6Guardrails

Limits in versioned YAML enforced by code. Research / paper / live modes. Circuit breakers on drawdown, daily loss, VIX, stale data and run cost. Kill switch. Idempotent orders.

7Observability

Every run, step, tool call, token, cache hit and dollar recorded. Lineage from an order back to the raw payload hash that justified it.

8Evals & learning

Crisis replays on every prompt, tool or policy change. Every view is falsifiable and Brier-scored. Post-mortems propose lessons; you accept them. The janitor removes drift weekly.

Golden rules

  1. Models judge; code computes, controls the flow and enforces limits.
  2. If it is not in the database with provenance, it does not exist.
  3. Only the Data Steward calls data APIs, and never downloads the same thing twice.
  4. Every number an agent states cites stored evidence, and the citation is checked.
  5. Outputs are typed contracts; invalid output goes back with a remediation note.
  6. Fewest tools per agent; research is read-only; no model reaches the broker.
  7. Risk limits change only through a PR you approve.
  8. You approve every trade until you decide otherwise.
  9. Replays are point-in-time; no look-ahead.
  10. Every step is reproducible from its stored context hash.
  11. Every view is falsifiable and gets scored.
  12. Clean up drift continuously, in small changes.

07 · From macro to exposure

Regime probabilities × playbook

The regime is never a single label. Four probabilities weight a playbook of sleeve scores (+2 strongly bullish to −2 strongly bearish). Code applies the modifiers; the CIO reviews them.

Inflation fallingInflation rising Growth rising
Goldilocks

Sell puts on equity indices and EM; condors on crude.

Reflation

Sell puts on crude, silver, EM and cyclicals; call spreads on TLT.

Growth falling
Deflationary bust

Call spreads on equities and crude; sell puts on TLT and gold.

Stagflation

Call spreads on equities; sell puts on gold; small crude puts if supply-driven.

Modifiers

  • Valuation. CAPE above its 80th percentile (20-yr): short-put size × 0.6, max 12Δ. Below the 30th: up to × 1.2.
  • Liquidity. 13-week global liquidity impulse: ±0.5 to risk-asset scores.
  • Stress. HY spreads widening fast or VIX curve inverted: spreads only, size × 0.5.
  • Vol richness. Size scales with the volatility-premium z-score; IV rank under 20 means small or skip.
  • Geopolitics. Severity-4+ event touching a sleeve: lower delta, defined risk only.
  • Disagreement. Desks split on a sleeve: conviction capped at 0.5.

08 · Implementation & risk

Out-of-the-money, defined where it matters, capped everywhere

All limits live in config/risk_policy.yaml and are enforced by code. A block cannot be overridden by any agent.

ViewStructureShort strikeNotes
BullishShort put, or put credit spread10–25Δ by convictionNaked puts only on index/ETF, ≤ 10% notional each, stress-tested. NG and silver: spreads only.
BearishCall credit spread10–20ΔNo naked calls. Upside gaps in commodities are unbounded.
Neutral, rich premiumIron condor10–16Δ each sideOnly when IV rank is above 30.
No edgeStand aside–Collateral still earns the hurdle.

Entry and management

  • 45 DTE target (21–75 allowed); expiries laddered, ≤ 30% of buying power in any week.
  • Conviction 0.5–0.6 → ~10Δ; 0.6–0.75 → ~16Δ; above 0.75 → 20–25Δ.
  • Take profit at 50% of credit. Exit at 21 DTE. Stop at a loss of 2× credit.
  • Defend when the short strike passes 0.35Δ. Roll only for a net credit.
  • No new short-vol risk 24h before FOMC, CPI or OPEC in affected sleeves; 72h before major elections.
  • Liquidity: open interest ≥ 500, bid-ask ≤ 10% of mid, spreads must pay ≥ 20% of width.
  • Phase 1 products: XSP/SPX, QQQ, IWM, EFA, EEM, FEZ, EWJ, FXI, INDA, EWZ, GLD, SLV, USO, UNG, XLE, TLT. Futures options in Phase 2.

10 · Build order

Roadmap

Each phase ends on a measurable exit test. Live trading is opt-in and only after paper results meet the promotion bar.

Phase 0 · now

Design

This blueprint, schema, configs, contracts.

Exit: your approval and answers.

Phase 1

Data plane

Migration, Data Steward, ~12 adapters, derived metrics, freshness page.

Exit: a second ingest downloads nothing; adapter contract tests pass.

Phase 2

Research desk

Charters, tools, context packs, validators, traces, 11 desks.

Exit: ≥ 95% valid on first try; 100% of citations resolve.

Phase 3

Committee

Regime model and strategist, CIO, red team, IC page.

Exit: crisis replays give sensible regimes; red team flags the known risk.

Phase 4

Implementation

Candidates, structurer, policy and stress engines, approvals, paper execution.

Phase 5

Learning

Monitor, attribution, calibration, lessons, janitor, alerts.

Phase 6 · opt-in

Live

Per-ticket approval, starting at 25% of target size.

Bar: ≥ 30 closed trades, positive excess after costs, DD < 8%, zero hard breaches, Brier ≤ 0.24.
