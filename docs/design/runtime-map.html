Macro Trader v2 · how it runs

Two kinds of machines, one database, and you.

The code lives in GitHub. GitHub's machines run the plain Python jobs every weekday. Anthropic's machines run the Claude agents on weekends, on your Pro plan. The two never call each other: they both read and write your Supabase database, and you make the final call on every trade.

Where does the code live?GitHub repositoryCode, configs, agent prompts and risk rules. Rule changes need your approval on a PR.
Where does the data live?SupabaseYour database: market data, reports, tickets, approvals, positions and logs.
Who runs downloads, checks and alerts?GitHub ActionsGitHub's servers, weekdays, plain Python. No AI and no Claude usage.
Where do the agents run?Claude Code cloudAnthropic's servers. All 19 agents run inside scheduled sessions on your Pro plan.
Does an agent call a GitHub script?NoEach place runs its own copy of the code from GitHub. They share work only through Supabase.
Who decides to trade?YouClaude proposes, code can veto, and nothing fills without your approval.

Inside one Claude Code cloud run

Saturday's Research A, step by step. The lead Claude conducts, but code decides which step is allowed next.

  1. The scheduled task fires. Anthropic starts a fresh container, copies the code from GitHub, and loads your keys and network allow-list.

    Anthropic

  2. The lead Claude opens the run's script (/research-a). It conducts the run but doesn't choose the order.

    Claude

  3. harness preflight checks that the kill switch is off, no API key is set, and critical data is fresh. If not, the run stops.

    Code

  4. harness packs builds each desk's briefing pack from Supabase: summary tables, last week's report, accepted lessons.

    Code

  5. The six desks run as sub-agents. Each reads its pack and queries Supabase through read-only tools, then writes its report.

    Claude

  6. harness submit checks the format, checks every cited number against Supabase, and checks freshness. Failures go back with a fix list, at most twice.

    Code

  7. harness next unlocks the next step only when the previous one is stored, so steps can't be skipped.

    Code

  8. Reports, usage and logs are saved in Supabase. The container is deleted when the session ends.

    Supabase

Resilience

When something breaks

Because the daily safety work runs on GitHub without Claude, losing Claude never stops risk monitoring.

Your Pro limit runs out mid-run

The run stops after its last saved step. It resumes after the reset, from that step. Daily marks, risk checks and alerts keep running on GitHub.

Claude is unavailable

No new trades are proposed that week. Open positions are still marked and checked by code, and alerts still reach you.

A GitHub job fails

GitHub emails you. The next run catches up, because the Data Steward downloads only what is missing.

Supabase is down

Both runners stop at preflight. Nothing trades without the database.

A data source is down

That series goes stale. If it is a critical series, the system drops to research-only mode until it is fresh again.

An agent writes a bad report

Code rejects it with a fix list. After two failures, last week's report is reused and flagged stale.
